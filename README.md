# TextMask

[![Tests](https://github.com/andreyqwerty365-netizen/textmask/actions/workflows/test.yml/badge.svg?branch=main)](https://github.com/andreyqwerty365-netizen/textmask/actions/workflows/test.yml)

Редактор подготовки обычного текста к передаче в ИИ. Заменяет поддерживаемые контакты и собственные точные строки на метки, сохраняя остальные символы и абзацы.

**HTML · CSS · JavaScript · Node.js 24 · Без зависимостей · [MIT](LICENSE)**

![TextMask: исходник с метками и результат, 1440 px](docs/screenshots/desktop.png)

Сценарий: подготовить письмо, заметку или фрагмент переписки для обсуждения с ИИ, заменив распознаваемые контакты и выбранные вручную строки на постоянные метки. Приложение помогает проверить замены до копирования; итог всегда требует просмотра человеком.

## Запуск

Из папки проекта, с установленным Node.js 24:

```sh
npm start
```

Откройте [TextMask на локальном компьютере](http://127.0.0.1:4175). Сервер слушает только `127.0.0.1:4175`. Остановка — `Ctrl+C`. `npm install` не требуется; сборки и CDN нет. Если порт занят, освободите его перед запуском.

```sh
npm test       # встроенный node:test: логика и HTTP
npm run check # проверка синтаксиса
```

`index.html` использует ES modules: запускайте через локальный сервер, а не через `file://`.

## Что умеет

- Вставка обычного текста. «Вставить пример» доступно, только когда исходник и список дополнительных строк совершенно пусты; команда защищена от перезаписи даже при прямом вызове. Пробельный ввод тоже считается рабочим.
- Email → `[EMAIL_1]`; российские телефоны → `[PHONE_1]`.
- Раскрываемая панель «Дополнительные замены»: точные строки, по одной на строку → `[TEXT_1]`. Regexp не используется.
- Повторы получают одну метку; форматирование телефона и регистр email не меняют его идентичность.
- На широком экране исходник и результат рядом, при ширине до 800 px — вкладки «Исходник / Результат». Переключение и изменение размера экрана сохраняют ввод.
- После обработки исходник показывает выделенные фрагменты вместе с метками. «Редактировать» возвращает поле ввода. Результат обозначен «Готов к проверке».
- Счётчики замен по типам и число уникальных меток; связанные пересечениями фрагменты учитываются по итоговому типу.
- Копирование через Clipboard API. При запрете результат выделяется и появляется инструкция `Ctrl+C` / `⌘C`.
- Очистка, клавиатурная навигация, `Ctrl+Enter` / `⌘+Enter`, клавиши стрелок/Home/End на мобильных вкладках, адаптивный интерфейс от 320 px. При Ctrl+Enter из исходника фокус переходит в результат; на мобильном — на вкладку результата.

После любого изменения ввода старый результат сбрасывается, поэтому скопировать устаревшую версию нельзя.

На встроенном синтетическом примере — 2 email-замены, 2 телефона и 2 ручные строки: всего 6 замен и 4 уникальные метки. Откройте пустую страницу → «Вставить пример» → «Маскировать» → проверьте исходник и результат → «Скопировать результат».

## Поддерживаемые правила

**Email.** ASCII: латинские буквы, цифры, `_`, `%`, `+`, `-`, апостроф и отдельные точки в локальной части; домен из меток с буквами, цифрами и внутренними дефисами; конечная зона — 2–63 латинские буквы. Например, `one.two+tag@sub.example.test` и `o'connor@example.test`. Сравнение всего email регистронезависимое — это сознательное упрощение, включая локальную часть. Полная RFC-валидация, Unicode-почта и адреса в кавычках не входят в правила.

**Телефоны.** Ровно 11 цифр, начало `+7` или `8`, затем группы `3–3–2–2`. Разрешены пробелы, табы, неразрывные пробелы, скобки вокруг трёхзначного кода, дефисы. Например, `+7 (999) 123-45-67`, `8 999 123 45 67`, `89991234567`. Они получат одну метку. Переносы строк внутри номера, добавочные и другие страны не поддерживаются. Принадлежность номера и действительность кода не проверяются.

**Ручные строки.** Буквальное регистрозависимое совпадение. Пробелы по краям непустой строки сохраняют значение. Пустые/пробельные строки и точные дубликаты игнорируются. Литерал не может содержать перенос строки. `C++[42]` скрывается целиком; символы `+`, `[`, `]`, `*` не становятся regexp.

**Границы.** До 100 000 единиц UTF-16 исходника; до 100 различных непустых ручных строк и 10 000 единиц UTF-16 в их поле; до 20 000 найденных совпадений до объединения. Превышение даёт явную ошибку и сбрасывает результат, без частичной обработки. Emoji могут занимать две единицы UTF-16.

## Пересечения и порядок токенов

1. Все совпадения ищутся в неизменённом исходнике. Ручные строки ищутся и с перекрытием, поэтому `abc`, `cde`, `def` полностью закроют `abcdef`.
2. Пересекающиеся интервалы объединяются транзитивно от самого левого начала до самого правого конца. Соседние, но не пересекающиеся интервалы остаются отдельными. Поэтому ни полный распознанный контакт, ни полный ручной литерал не останутся частично открытыми из-за конкурирующей замены.
3. Идентичности, встретившиеся в одном объединении, связываются во всём тексте. Их повторы в других местах также получают общую метку. Это намеренно консервативно: широкий ручной литерал может связать несколько разных контактов.
4. Тип всей связанной группы определяется приоритетом `EMAIL → PHONE → TEXT`. Например, ручная строка, пересекающая email и телефон, объединит их в метку `EMAIL`; повтор телефона в другом месте тоже получит эту метку. Интерфейс показывает число объединённых фрагментов под предпросмотром.
5. Нумерация по типу идёт по первому появлению итоговой группы слева направо. Уже имеющиеся в исходнике метки вида `[EMAIL_1]` резервируются и пропускаются, чтобы не совпасть с новыми.

Например, исходник `anna@example.test anna` и ручная строка `anna` дают `[EMAIL_1] [EMAIL_1]`. Это защищает email целиком и сохраняет одинаковый токен ручного повтора.

## Приватность и ограничения

Текст обрабатывается в памяти вкладки. Приложение не использует localStorage, sessionStorage, cookies, базу данных, аналитику, URL с текстом или журналы пользовательского ввода. Сервер отдаёт только фиксированный список статических ресурсов, не принимает POST и не записывает запросы. CSP запрещает соединения страницы через `connect-src 'none'`. Сетевые обращения при загрузке — только к локальным ресурсам приложения.

Перезагрузка и уход со страницы очищают поля, включая восстановление страницы из bfcache. При явном копировании текст попадает в системный буфер обмена; его дальнейшее хранение определяется системой. Приложение не защищает от расширений браузера, снимков экрана или чужого доступа к компьютеру.

Это помощник для маскирования, не гарантия полного обезличивания и не шифрование. Имена, адреса, документы, редкие форматы и данные в свободной форме автоматически не распознаются. Сверяйте результат вручную, добавляйте точные строки. Документы, PDF и изображения не поддерживаются; сохранения истории и обратной расшифровки меток нет.

Демо содержит только вымышленные значения и домен `.test`; контактировать с указанными телефонами не нужно.

## Структура и проверки

```text
src/mask.js                 чистая логика поиска, объединения и замены
src/app.js                  DOM, состояния, подсветка, копирование и очистка
src/demo.js                 синтетический пример
server.js                   статический локальный HTTP-сервер
test/                       node:test: логика, DOM-контроллер и HTTP
docs/TESTING.md              проверенные сценарии и границы проверки
docs/DESIGN.md               происхождение оформления и ассетов
docs/screenshots/            реальные снимки интерфейса
.github/workflows/test.yml   Node.js 24: Ubuntu / Windows
```

Обработка проходит цепочку: поиск в исходном тексте → объединение пересечений → связывание повторов → назначение меток → сборка результата из неизменённых участков и замен. Чистая функция маскирования не зависит от DOM. Интерфейс строит подсветку текстовыми узлами и сбрасывает старый результат при редактировании.

Проверки и фактические ограничения окружения: [TESTING.md](docs/TESTING.md). Идеи следующих версий: [BACKLOG.md](docs/BACKLOG.md). GitHub Actions выполняет npm test без установки зависимостей; синтаксис можно проверить отдельно командой npm run check.
